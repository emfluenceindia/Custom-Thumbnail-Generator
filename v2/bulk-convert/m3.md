## Feature context

## Scope

Add a clearly separate bulk WebP conversion button to the existing settings page. Add an individual WebP conversion action for every displayed thumbnail-size row, including WordPress core sizes, active-theme sizes, and plugin-defined custom sizes — this requires adding a new action column/markup to the default sizes table (`ctgen_render_default_thumbnail_list_table()`) in addition to extending the existing action column in the custom sizes table. Use a distinct class/action and accessible label/title so these controls cannot trigger the existing regenerate or remove handlers. The bulk action converts all existing supported thumbnail sizes; a row action converts only that size across eligible image attachments.

Use the milestone 2 backend endpoints. Discover eligible attachment IDs, then process them sequentially (or in another bounded way supported by the existing architecture) — do not submit one unbounded request for an entire media library, and do not copy the existing per-row regenerate action's unbounded single-request pattern. For the bulk action, ask the backend to convert all existing thumbnail sizes for each attachment. For a row action, pass only that row's validated size slug. Send the existing nonce and handle authorization expiry, network errors, malformed responses, skipped files, and per-item failures without falsely reporting success or abandoning later items — explicitly check each response's actual success/failure/skip outcome before advancing the counters, unlike the existing bulk-regenerate loop.

Implement a real-time progress bar for conversion, visually consistent with the existing regenerate progress UI but independently identified and managed (distinct element IDs/classes; do not reuse `#ctgen-progress`, `#ctgen-progressbar`, `#ctgen-percentage-increment`, or `#ctgen-generator-status`). It must update as work completes, display a numeric percentage and useful current/total or converted/skipped/failed counts, and reach an accurate terminal state on success, partial failure, cancellation/error, and empty work queues. Prevent duplicate concurrent conversion runs (disable the triggering control while a run is in progress, matching the existing `#ctgen-regenerate` disable-during-run pattern) and prevent conversion clicks from accidentally invoking regeneration. Keep regeneration's existing progress and behavior unchanged.

Use event delegation (bound to a stable ancestor such as `#ctgen-thumb-list`, matching the existing pattern) for any control inside the dynamically reloaded custom-size table. Keep selectors, data attributes, and operation state specific to conversion. Ensure controls and progress feedback remain keyboard accessible, have meaningful accessible names, and expose progress updates to assistive technology (e.g. `aria-live="polite"` on the status text, not on the whole progress bar) without flooding announcements. Translate new user-facing strings using the `custom-thumbnail-generator` text domain and follow the existing script localization/enqueue patterns (`wp_localize_script`, `admin_enqueue_scripts`).

Follow the repository's asset convention. The plugin currently ships only a minified script with no source file — do not hand-edit the minified file as your only source of truth going forward. Establish the smallest maintainable source/update approach: at minimum, keep a maintained, readable, unminified source file for the script (e.g. alongside the existing file) and ensure the actual enqueued `.min.js` is regenerated from it and demonstrably contains the tested behavior — do not let the enqueued file and your "source" drift apart. Avoid unrelated CSS or UI restyling.
